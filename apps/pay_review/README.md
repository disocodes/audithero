# AuditHero Roster Pay Simulator & Review

This Databricks App is the interactive write-back companion to the AuditHero AI/BI dashboard.

It is designed for the common situation where **roster/timesheet evidence exists before complete payroll evidence is available**.

## What it does

For each employee, year and SCHADS scenario already calculated by AuditHero, the app shows:

- rostered/derived worked hours;
- the effective SCHADS minimum base rate;
- the full minimum entitlement already calculated by the Award engine;
- fixed Award-linked components such as allowances that should not simply scale with a hypothetical base rate;
- a continuous rate-sensitive pay equation;
- an **Award-multiplier** what-if model;
- a **flat/loaded hourly-rate** what-if model;
- break-even hourly rates for both models;
- a live rate slider from the applicable Award base rate to at least $100/hour;
- shift-by-shift simulated outcomes and review flags;
- manual/base-rate confirmation with source reference and notes;
- confirmation history rather than destructive overwrite;
- a master CSV export; and
- an Excel workbook containing the master review, all scenario outcomes and confirmation history.

## Interpretation

The simulation layer does **not** invent actual payroll.

- `award_minimum_entitlement` is the deterministic SCHADS entitlement produced by AuditHero.
- `simulated_pay` is hypothetical and responds to the selected hourly rate/pay model.
- a saved hourly rate confirms that rate evidence only; it does not prove total gross pay.
- actual payroll files loaded later through the normal Preview -> Reviewed Uploaded Files workflow remain the preferred source for definitive reconciliation.

## Pay models

### Base + SCHADS multipliers

The selected base hourly rate is used wherever the already-calculated scenario is rate-sensitive. Fixed Award-linked amounts remain fixed.

This answers questions such as:

> If this employee's base rate was $47.50 and payroll applied the SCHADS penalty/overtime structure, what would the roster imply they were paid?

### Flat / loaded hourly rate

The selected rate is multiplied across rostered worked hours, plus fixed Award-linked components.

This answers questions such as:

> If the employer says the employee received a flat $55/hour, would that loaded rate cover the minimum roster entitlement generated by SCHADS penalties/overtime?

A result that numerically covers the minimum is still not treated as definitive compliance where set-off/loaded-rate evidence, payroll amounts, classifications, breaks or other Award facts remain unresolved.

## Setup

After deploying/upgrading the AuditHero bundle:

1. run **AuditHero - Setup**;
2. run **AuditHero - Setup Pay Simulation & Review** once;
3. run the normal **Preview Uploaded Files -> Audit Reviewed Uploaded Files** workflow for roster/timesheet evidence; and
4. open the Databricks App **audithero-pay-review**.

The simulation setup job creates:

- `silver.pay_rate_confirmations`
- `gold.v_pay_simulation_terms_latest`
- `gold.v_pay_simulation_employee_year`
- `gold.v_pay_rate_confirmations_latest`
- `gold.v_pay_simulation_master`

and grants the app service principal only the required Unity Catalog privileges.

## Confirmation behavior

A confirmation is stored per employee/year with:

- exact hourly rate;
- effective year dates;
- pay model;
- selected SCHADS scenario used for review;
- evidence source type;
- source/reference;
- notes;
- confirming Databricks user;
- timestamp; and
- previous confirmation ID.

Saving a new confirmation does not delete the old one. `v_pay_rate_confirmations_latest` selects the newest active confirmation while the Delta table retains the full history and has Change Data Feed enabled.

## Later payroll evidence

When payroll Excel/CSV becomes available, upload it through the normal AuditHero intake. The existing Actual vs Expected reconciliation remains the definitive payroll comparison. The rate-confirmation record can stay as supporting evidence and an audit trail of what was known before payroll was obtained.
